# Продажа и запуск сайта ресторана

## Демо для нового лида за 15–30 минут

1. Откройте `config/business.ts`.
2. Замените `name`, `shortName`, `tagline`, `description`.
3. Укажите публичные телефон, город, адрес и адрес самовывоза.
4. Укажите SEO-заголовок и описание.
5. Не добавляйте в этот файл пароли, токены, ИНН или другие неподтверждённые данные.
6. Замените `apps/storefront/public/images/shaverma-logo.jpg`.
7. При необходимости замените `apps/storefront/public/icon.svg`.
8. OG-картинка формируется кодом в `apps/storefront/src/app/opengraph-image.tsx`.
9. Запустите `npm ci`, если зависимости ещё не установлены.
10. Скопируйте `.env.example` в `.env` и заполните локальные URL и ключи.
11. Выполните `npm run setup:check`.
12. Выполните `npm run setup:db`.
13. Первый раз выполните `npm run admin:bootstrap`.
14. Запустите `npm run dev:platform` и `npm run dev:storefront` в двух терминалах.
15. Откройте `http://localhost:3001/admin/login`.
16. В «Каталог» замените названия, состав, цены и фото.
17. В «Настройки» оставьте «Заказы без онлайн-оплаты».
18. Включите «Разрешить тестовые заказы».
19. На витрине добавьте блюдо и оформите тестовый заказ.
20. Покажите этот же заказ в «Заказы» с оранжевой меткой.

## После оплаты: запуск клиента

1. Создайте отдельную БД, Blob Store и два Vercel-проекта для клиента.
2. Не используйте ключи другого ресторана.
3. Подключите репозиторий `Website-for-sale`, ветку `main`.
4. Для обоих проектов оставьте Root Directory корнем репозитория.
5. Проект витрины: Build Command `npm run build:storefront`.
6. Проект витрины: Output Directory `apps/storefront/.next`.
7. Проект платформы: Build Command `npm run build:platform`.
8. Проект платформы: Output Directory `apps/platform/.next`.
9. Install Command для обоих: `npm ci`.
10. Добавьте переменные из `.env.example` в нужные проекты.
11. Выполните миграции и начальное заполнение один раз.
12. Создайте первого администратора.
13. В `/admin/users` создайте администратора клиента.
14. Передайте MFA URI и recovery-коды отдельным защищённым каналом.
15. Проверьте витрину, тестовый заказ и админку.
16. Затем подключите домены.
17. Реальную оплату включайте последней.

## База данных — самый простой путь

Рекомендуемый вариант: Prisma Postgres через Vercel Marketplace.

1. В Vercel откройте проект платформы.
2. Откройте Storage → Create Database.
3. Выберите Prisma Postgres и регион рядом с пользователями.
4. Подключите базу к проекту платформы.
5. Скопируйте выданную строку в `DATABASE_URL`.
6. Если выдан отдельный direct URL, добавьте его как `DIRECT_URL`.
7. Те же DB-переменные добавьте только туда, где запускаются Prisma-команды.
8. Локально создайте `.env`; этот файл игнорируется Git.
9. Выполните `npm run setup:check`.
10. Выполните `npm run setup:db`.
11. Команда запускает generate, `prisma migrate deploy` и безопасный seed.
12. Повторный seed не перезаписывает изменённый владельцем каталог и настройки.
13. Проверка схемы: `npm run prisma:validate`.
14. Проверка миграций: `npm run prisma:migrate:deploy`.
15. Проверка данных: войдите в админку; должны быть категории, товары, зона и часы.
16. Проверка записи: оформите тестовый заказ и найдите его в «Заказы».

### Если БД опять бесит

1. `P1001 / can’t reach database`: проверьте хост, порт, allowlist и паузу БД; повторите migrate.
2. `password authentication failed`: заново скопируйте полный `DATABASE_URL`, включая пароль и SSL-параметры.
3. `migration failed`: не делайте reset; исправьте доступ и повторите `npm run prisma:migrate:deploy`.
4. `prepared statement already exists`: используйте URL/режим pooling, рекомендованный провайдером, а миграции запускайте через `DIRECT_URL`.
5. `table does not exist`: убедитесь, что команда смотрит в ту же БД и schema; затем выполните `npm run setup:db`.

## Админка

Адрес: `https://<домен-platform>/admin/login`.

Первый администратор:

1. Задайте `ADMIN_BOOTSTRAP_EMAIL`, `ADMIN_BOOTSTRAP_PASSWORD`, `MFA_ENCRYPTION_KEY`.
2. Пароль должен быть не короче 14 символов.
3. Выполните `npm run admin:bootstrap`.
4. Сохраните MFA URI и десять recovery-кодов из терминала.
5. Удалите bootstrap email/password из Vercel после создания.

Передача клиенту:

1. Войдите как первый администратор.
2. Откройте «Пользователи».
3. Создайте роль «Администратор клиента».
4. Сохраните показанные один раз MFA URI и recovery-коды.
5. Клиент вводит первый TOTP-код при входе; MFA отмечается подтверждённой.
6. Кнопка «Отозвать доступ» закрывает активные сессии.
7. «Сбросить пароль» меняет пароль и закрывает активные сессии.
8. Для сотрудника без настроек создайте роль «Менеджер».

Каталог находится в `/admin/catalog`: название, состав, рублёвая цена, фото, доступность.
Настройки находятся в `/admin/settings`: режим, тестовые заказы, зоны, часы и маршрутизация оплаты.

## Режимы сайта

Все режимы переключаются в «Админка → Настройки», без изменения кода.

- `MENU_ONLY` / «Только меню»: каталог и контакты работают; корзина и checkout скрыты, прямой checkout закрыт.
- `ORDERS` / «Заказы без онлайн-оплаты»: заказ сохраняется, оплата — наличными или картой при получении.
- `ONLINE_PAYMENT` / «Заказы с онлайн-оплатой»: заказ и платёжная попытка сохраняются, затем вызывается выбранный эквайер.
- «Разрешить тестовые заказы»: показывает безопасный тестовый чекбокс в checkout.
- Тестовый заказ всегда проходит обычную серверную проверку цен и сохраняет Order/OrderItems.
- Тестовый заказ не создаёт PaymentAttempt, не вызывает эквайер и помечается в админке.
- Переключение режима не удаляет товары, настройки или старые заказы.

## Фото / Vercel Blob

1. В Vercel откройте проект платформы.
2. Storage → Create → Blob.
3. Подключите Blob к платформе.
4. Проверьте наличие `BLOB_READ_WRITE_TOKEN` в Production и Preview.
5. Перезапустите deployment платформы.
6. Откройте `/admin/catalog`.
7. Выберите JPG, PNG, WebP или AVIF до 8 МБ.
8. Нажмите «Сохранить».
9. Обновите витрину; фото должно прийти с `*.public.blob.vercel-storage.com`.

## Оплата

Текущий статус: CODE READY — EXTERNAL PAYMENT SETUP/TEST REQUIRED.

YooKassa:

1. Получите test shop ID и secret key в кабинете YooKassa.
2. Добавьте `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` в платформу.
3. Webhook: `https://<домен-platform>/api/webhooks/yookassa`.
4. В админке назначьте YooKassa для CARD и/или SBP.
5. Проведите один sandbox-платёж и проверьте PAID только после webhook/server verification.

Т-Банк:

1. Получите тестовые terminal key и password.
2. Добавьте `TBANK_TERMINAL_KEY`, `TBANK_PASSWORD` в платформу.
3. Notification URL: `https://<домен-platform>/api/webhooks/tbank`.
4. В админке назначьте Т-Банк нужному способу.
5. Проведите один тест и проверьте подпись, сумму и итоговый статус.

Без ключей `ONLINE_PAYMENT` закрывается с ошибкой настройки и не имитирует оплату.
Redirect успеха не помечает заказ оплаченным.

## Домен

1. В Vercel → storefront → Settings → Domains добавьте публичный домен.
2. В Vercel → platform → Settings → Domains добавьте `admin.` или `api.` поддомен.
3. Обновите `NEXT_PUBLIC_SITE_URL` публичным HTTPS URL.
4. Обновите `NEXT_PUBLIC_PLATFORM_API_URL`, `PLATFORM_API_URL`, `ADMIN_BASE_URL` URL платформы.
5. В `ALLOWED_STOREFRONT_ORIGINS` укажите точный origin витрины без завершающего `/`.
6. Перезапустите оба deployment.
7. Обновите webhook URL в кабинетах эквайеров.

## Перед показом лиду

1. Витрина открывается на телефоне.
2. Название, логотип, телефон и меню соответствуют лиду.
3. Режим `ORDERS`, тестовые заказы включены.
4. В корзину добавляется товар.
5. Тестовый заказ создаётся и сразу виден в админке.
6. На нём есть метка «Тестовый заказ».

## Перед реальными заказами

1. Заполнены фактические реквизиты и контакты оператора.
2. Утверждены юридические тексты; `LEGAL_DOCS_APPROVED=true`.
3. Проверены цены, зоны, минимальная сумма и все семь дней работы.
4. Создан клиентский администратор, bootstrap-секреты удалены.
5. Выполнен `npm run launch-check`.
6. Для `ONLINE_PAYMENT` пройден sandbox-тест выбранного эквайера.
7. Тестовые заказы выключены, если они больше не нужны.

## Если деплой сломался

1. Build: проверьте Root Directory, build command и Node-версию; локально запустите оба `npm run build:*`.
2. `DATABASE_URL`: проверьте, что переменная добавлена в platform Production и сделан redeploy.
3. Prisma migration: выполните `npm run prisma:migrate:deploy`; не используйте `migrate reset` на production.
4. Platform URL/CORS: URL должны быть HTTPS, а origin витрины — точным значением в `ALLOWED_STOREFRONT_ORIGINS`.
5. Admin login: проверьте `ADMIN_BASE_URL`, cookie HTTPS, MFA-код и время устройства.
6. Blob: подключите Store, добавьте token, redeploy платформы, загрузите поддерживаемый файл до 8 МБ.
7. Webhook: проверьте публичный HTTPS URL, ключ провайдера и отсутствие редиректа на callback-пути.
